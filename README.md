# logsGuard

Учебный проект на Bash для GNU/Linux с systemd. `/LOGS` — отдельная
смонтированная файловая система с каталогами `auth_service`,
`data_process_service`, `system_event_handler_service`. Таймер запускает
проверку через минуту после загрузки и затем каждые пять минут.

## Правила обработки

1. `df` сообщает заполнение ниже `THRESHOLD` — ничего не изменяется.
2. При заполнении **не ниже** порога лимит каждого каталога равен
   `размер файловой системы × THRESHOLD / 100 / 3` (целые байты, округление вниз).
3. `du -s -B1` учитывает выделенное место всего каталога, включая архивы.
   Обрабатываются только каталоги **строго больше** лимита.
4. Выбираются только обычные файлы верхнего уровня с окончанием `.log`.
   Символические ссылки не выбираются. Самый новый лог определяется как
   **последнее имя в побайтовом порядке `LC_ALL=C`**, а не по времени изменения.
   Используйте имена с датами фиксированной ширины, например `service_2026_10_22_001.log`.
5. Остальные логи архивируются настоящим `tar` в уникальный `.part` внутри
   того же каталога. При ошибке чтения, записи, ENOSPC или любой ошибке `tar`
   временный архив удаляется, исходники сохраняются.
6. Успешный архив публикуется как `.tar.gz` атомарным созданием жёсткой ссылки
   (`ln -T`, без перезаписи существующего имени), временное имя удаляется.
   Только затем удаляются исходники. Ошибка удаления возвращает ошибку,
   архив остаётся. Ошибки отдельных компонентов накапливаются.
7. Повторный `df` сообщает, если места всё ещё недостаточно. Архивы автоматически
   не удаляются и повторно не упаковываются.

Список файлов передаётся массивами, `find`/`sort` используют NUL-разделители:
пробелы, переводы строк и начальный дефис в имени безопасны. `flock` удерживается
на открытом каталоге точки монтирования до завершения процесса; ручной запуск
и systemd используют одну блокировку без удаляемого lock-файла.

## Установка и настройки

Требуются Bash 4.4+, GNU coreutils/findutils/tar с gzip, util-linux (`flock`,
`mountpoint`, `mount`), systemd; для создания демонстрационного образа — e2fsprogs.
Для тестов нужен Python 3 (только стандартная библиотека). Основной скрипт и
монтирование требуют root. Подмены команд предназначены только для тестов;
при рабочем запуске используйте доверенный PATH и защищённые от посторонней
записи каталоги.

```bash
sudo ./install.sh
sudoedit /etc/default/logs-guard
sudo systemctl restart logs-mount.service
sudo systemctl start logs-guard.service
systemctl list-timers logs-guard.timer --no-pager
journalctl -u logs-guard.service -n 30 --no-pager
```

Установка копирует скрипты и юниты, создаёт `/etc/default/logs-guard`, если его
ещё нет, и включает монтирование и таймер. Существующая конфигурация сохраняется.
Оба сервиса читают этот файл. Конфигурацию источника задайте **до установки**
в `logs-guard.conf`, если демонстрационный образ при первом запуске не нужен.
Смена источника требует ручного размонтирования прежнего `/LOGS`: уже
смонтированная точка не перемонтируется автоматически.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `THRESHOLD` | `90` при отсутствии переменной | Целое 1–100; пустое значение — ошибка |
| `LOGS_DIR` | `/LOGS` | Точка монтирования для проверки |
| `MOUNT_POINT` | `/LOGS` | Точка монтирования для mount_logs.sh |
| `LOGS_UUID` | пусто | UUID заранее подготовленного настоящего раздела |
| `IMAGE` | `/var/lib/logs.img` | Loop-образ, если UUID не указан |
| `IMAGE_SIZE` | `200M` | Размер только нового образа |

`THRESHOLD` допускает от одной до трёх ASCII-цифр. Ведущие нули десятичные:
`001` = 1, `010` = 10, `090` = 90. `000`, `0001`, отрицательные значения,
пробелы, дроби, строки и числа длиннее трёх цифр отклоняются **до любых изменений**.
Явно пустые пути не заменяются значениями по умолчанию и приводят к ошибке.

Для настоящего раздела получите UUID через `lsblk -f` и укажите:

```ini
LOGS_UUID=12345678-abcd-1234-abcd-123456789abc
MOUNT_POINT=/LOGS
LOGS_DIR=/LOGS
THRESHOLD=90
```

`mount_logs.sh` вызывает `mount -U UUID`; существующий раздел **никогда не
форматируется**. При отсутствии UUID используется loop-образ: новый создаётся
и форматируется в ext4, существующий только монтируется. Родительский каталог
образа должен существовать. Каталоги компонентов создаются после монтирования.

Ручной запуск:

```bash
sudo env THRESHOLD=80 LOGS_DIR=/LOGS ./logs_guard.sh
sudo env LOGS_UUID=12345678-abcd-1234-abcd-123456789abc ./mount_logs.sh
# Демонстрационный режим:
sudo env IMAGE=/var/lib/logs.img IMAGE_SIZE=200M ./mount_logs.sh
```

## Коды завершения logs_guard.sh

| Код | Значение |
| --- | --- |
| 0 | Проверка успешна, заполнение ниже порога |
| 1 | Ошибка выполнения: df/du/find/sort/tar/публикация/удаление и т. п. |
| 2 | Ошибка окружения: root, команды, монтирование, каталоги, доступ |
| 3 | Некорректный THRESHOLD |
| 4 | Другой экземпляр уже работает |
| 5 | Выполнение успешно, но раздел всё ещё достиг или превысил порог |

Код 1 приоритетнее кода 5. Systemd помечает любой ненулевой код как неуспешный
запуск, в журнале указана причина. `mount_logs.sh` и `install.sh` возвращают 0
при успехе, ненулевой код при ошибке (детальные коды у них не являются API).

## Автотесты

```bash
./test_logs_guard.sh                     # быстрые тесты + попытка интеграционных
python3 -m unittest discover -s tests -p test_fast.py -v
sudo ./tests/integration.sh              # реальные loop/ext4, включая ENOSPC
bash -n logs_guard.sh mount_logs.sh install.sh test_logs_guard.sh tests/integration.sh
```

Быстрый уровень запускает неизменённый основной скрипт с управляемым PATH:
подменяются root/mountpoint, результаты df/du и команды с внедряемыми отказами.
Архивация, контрольные суммы, публикация и блокировка проверяются настоящими
командами, кроме сценария принудительного отказа соответствующей команды.
В частности ошибка чтения моделируется отказом tar на одном исходнике;
она не выдаётся за реальный аппаратный сбой.

Интеграционный уровень создаёт **уникальный** каталог `mktemp`, полностью
выделенный образ 64 MiB, ext4 и приватную точку монтирования внутри каталога.
Рабочий `/LOGS`, существующие образы и чужие точки не используются.
Подготовка проверяется; очистка выполняется через `trap`. Если размонтирование
не удалось, образ и каталог сохраняются и сообщается ошибка, чтобы не удалить
содержимое смонтированной системы. Нет root/команд/возможности mount — явный
`SKIP`, а не утверждение об успешном прохождении. Другие ошибки подготовки — сбой.

Для ENOSPC исходники и заполнитель пишутся из `/dev/urandom`; тест требует
реального `No space left on device` и затем такой же ошибки от tar.
`truncate` для проверки занятого места не используется. В успешных сценариях
нули записываются через `dd`, занимая реальные блоки; сжатие там намеренное.

### Сценарий → ожидаемый результат → проверка

| Сценарий | Ожидаемый результат | Чем проверяется |
| --- | --- | --- |
| Раздел ниже порога, даже при превышении доли | 0, без изменений | fast `boundaries_and_selection`, loop `below` |
| Ровно порог | Проверка каталогов запускается | fast `boundaries_and_selection` |
| Каталог ровно равен лимиту | Без архивации | fast `boundaries_and_selection` |
| Превышение в одном/двух/трёх каталогах | Только нужные архивируются | fast `boundaries_and_selection`, loop `one_two_three` |
| Пустой каталог, единственный лог, symlink | Исходники/ссылка сохраняются | fast `empty_single_and_symlink`, loop `single_large_current` |
| Раздел заполнен посторонним файлом | Нет архивации, 5 | loop `nonlogs_and_single` |
| THRESHOLD 1, 100, отсутствует | Допускаются, default 90 | fast `thresholds` |
| Пусто, 0, -1, 101, 1.5, abc, пробелы, длинное число | 3, без изменений | fast `thresholds` |
| Ведущие нули | Десятичные, максимум три цифры | fast `thresholds` |
| Нет root/mount/компонента | 2, без изменений | fast `environment`, loop после umount |
| Нет команды/прав доступа | 2, без изменений | fast `access_and_missing_command` (права при непривилегированном запуске) |
| Ошибка df/du, некорректный вывод | 1, до архивации | fast `command_failures` |
| Ошибка find/sort | 1, без удаления логов | fast `command_failures` |
| tar с частичным архивом, ошибка записи | 1, исходники сохранены, .part удалён | fast `command_failures` |
| Реальная нехватка места | Ошибка записи tar, 1, без потери исходников | loop `real_enospc` |
| Ошибка чтения одного файла | 1; другой компонент обработан | fast `read_failure_and_other_component` |
| Ошибка удаления | 1, архив сохранён; другой компонент обработан | fast `delete_error_and_aggregate` |
| Совпадение окончательного имени | Существующий архив сохранён, 1 | fast `collision`, настоящий ln |
| Повторный запуск | Архивы не перепаковываются | fast `repeat_and_post_usage` |
| Два одновременных запуска | Второй получает 4, один архив | fast `concurrent`, настоящий flock |
| После обработки осталось ≥ порога | Явное сообщение и 5 | fast `repeat_and_post_usage`, loop `nonlogs_and_single` |
| После обработки стало ниже порога | 0 | fast `post_check`, loop `one_two_three` |
| Повторный df не сработал | 1, не сообщение об успехе | fast `post_check` |

Архивы проверяются по **точному списку имён** и SHA-256 прочитанного из архива
содержимого. Отдельно сверяются текущие логи и необрабатываемые каталоги.
При сбоях сверяются исходники и отсутствие `.part`; проверяются сообщения и коды.
Фактический протокол последнего запуска: [TEST_RESULTS.md](TEST_RESULTS.md).

## Ограничения

Блокировка согласует только экземпляры logs_guard.sh. Производители логов должны
писать в текущий файл и не изменять старые имена во время архивации; защита от
враждебной подмены файлов и каталогов здесь не реализована. Успешное завершение
tar не гарантирует сохранность при внезапном отключении питания (нет fsync и
транзакции нескольких unlink). При частичном отказе удаления часть исходников
может остаться вместе с полноценным архивом. При запрете удаления самого `.part`
очистка тоже может завершиться ошибкой ОС; диагностическое сообщение rm сохранится.

Нужны файловая система с поддержкой hard links и flock и достаточно места для
**полного** архива до удаления исходников. Оценка сжатия заранее не делается:
решение принимает реальный результат tar. Несжимаемые данные могут не освободить
места. `df` округляет проценты, `du` учитывает выделенные блоки и может иначе
учитывать hard links между каталогами; квоты и специальные FS требуют адаптации.
Проверки окружения не заменяют обработку ошибок фактических операций.
Архивы сохраняются без срока удаления: когда они заполнят раздел, требуется
внешнее хранение или отдельная явно настроенная политика.
